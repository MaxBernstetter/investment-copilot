# Frontend

The user frontend (`src/frontend/`) is a static React single-page app that calls only the public `access` API. It is deployed to GitHub Pages (see [[0005-react-spa-on-github-pages]]).

## Stack

| Part | Choice |
|---|---|
| UI | React 19, TypeScript |
| Build and dev server | Vite 7 |
| Charts | Plotly.js (`plotly.js-dist-min`) |
| Unit tests | Vitest 5 with jsdom, Testing Library, jest-dom |
| Lint | ESLint 9 with typescript-eslint and react-hooks rules |
| API client | `openapi-fetch`, types generated by `openapi-typescript` from `src/contracts/openapi/access/v1.json` |

Dependencies are pinned to exact versions in `package.json`; `package-lock.json` is committed and is never edited by hand.

## Generated API client

`frontend:generate` writes `src/api/schema.d.ts` from the access OpenAPI document. The file is git-ignored and regenerated by every task that lints, type-checks, tests, builds or runs the app, so the types cannot drift from the contract. `src/api/client.ts` exports the typed `api` client, which calls `VITE_ACCESS_URL`.

## Curve view

The page shows the ECB euro area AAA spot curve (`curve_id` `ecb-aaa-spot`) after the health check passes.

- **Latest curve:** on open, the view calls `GET /v1/curves/{curve_id}/observations` without `valid_date`; the date input then shows the `valid_date` the API returned.
- **Valid date:** picking a date refetches for that date. Clearing the input returns to the latest curve.
- **Gaps:** maturities without a published value (`value: null`) are plotted as gaps, not zeros, and listed under the chart ("No value for: …"). Points keep the API's grid order.
- **Errors:** 404 shows "No data known for this date."; 422 and other errors show the problem `detail`; 503 or an unreachable API shows the offline alert.
- **Attribution:** the page credits [ECB statistics](https://data.ecb.europa.eu/) as the source.

| Path | Content |
|---|---|
| `src/curve/CurveView.tsx` | Curve page: date input, state messages, source |
| `src/curve/CurveChart.tsx` | Plotly line chart with markers, gaps unconnected |
| `src/curve/fetchCurve.ts` | API call and mapping of responses to `CurveResult` |
| `src/curve/curveData.ts` | Chart series and missing maturities |

## Time travel

The "Known as of" control shows the curve as it was known at a chosen time (the API's `as_of`, the transaction-time axis, separate from the valid date).

- **Control:** a `datetime-local` input, read as local time and sent as UTC ISO. "Now" clears it and returns to the latest knowledge.
- **URL:** the choice is kept in the `as_of` query parameter, so a link reproduces the view. A missing or unparseable `as_of` is ignored. Changes use `history.replaceState`, so they add no history entries.
- **Banner:** while `as_of` is set the page shows "Showing the curve as known on …" in UTC.
- **No data:** if nothing was known at that time (404), the page shows "No data known as of …"; a 422 shows the problem `detail`.

| Path | Content |
|---|---|
| `src/asOf.ts` | Read and write `as_of` in the URL; local and UTC conversion |
| `src/curve/AsOfControl.tsx` | "Known as of" input and "Now" button |

## Offline state

On mount the app calls `GET {VITE_ACCESS_URL}/health` (`src/backend.ts`). A `2xx` response shows the curve view; a non-2xx response or a network error shows a `role="alert"` message ("Backend offline: the YieldLens API is not reachable. Try again later."). While the check runs, the page shows "Loading…".

## Tasks

Run from the repository root with `devbox run -- task frontend:<task>` (see [[13-build-and-ci]]):

| Task | Does |
|---|---|
| `frontend:setup` | `npm ci` from the lockfile |
| `frontend:audit` | `npm audit --audit-level=high`; fails on high or critical findings |
| `frontend:generate` | Generate `src/api/schema.d.ts` from the access OpenAPI document |
| `frontend:fmt` | ESLint with `--fix` |
| `frontend:lint` | ESLint |
| `frontend:typecheck` | `tsc -b` (app and Vite config) |
| `frontend:test:unit` | Vitest, single run |
| `frontend:build` | Production bundle in `dist/` |
| `frontend:dev` | Vite dev server |

CI runs `setup`, `audit`, `lint`, `typecheck`, `test:unit` and `build` in `.github/workflows/frontend.yml`; each of them generates the API types first, so CI needs no separate step.
