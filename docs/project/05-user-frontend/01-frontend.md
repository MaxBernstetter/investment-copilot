# Frontend

The user frontend (`src/frontend/`) is a static React single-page app that calls only the public `access` API. It is deployed to GitHub Pages (see [[0005-react-spa-on-github-pages]]).

## Stack

| Part | Choice |
|---|---|
| Build and dev server | Vite 7 |
| UI | React 19, TypeScript, Mantine 9 (`@mantine/core`, `@mantine/hooks`), theme in `src/theme.ts`; see [[0018-mantine-ui-and-charts]] |
| Icons | `@tabler/icons-react`, named imports only (see the icons addendum in [[0018-mantine-ui-and-charts]]) |
| Charts | `@mantine/charts` (Recharts), lazy-loaded; see [Charts](#charts) |
| Unit tests | Vitest 5 with jsdom, Testing Library, jest-dom |
| Lint | ESLint 9 with typescript-eslint and react-hooks rules |
| API client | `openapi-fetch`, types generated by `openapi-typescript` from `src/contracts/openapi/access/v1.json` |

Dependencies are pinned to exact versions in `package.json`; `package-lock.json` is committed and is never edited by hand.

## Views

The views are built from Mantine components: `Title` for headings, `TextInput` and `NativeSelect` for controls (native inputs underneath, so date and time pickers stay browser-native), `Button` for actions, `Alert` for the as-of banner (`role="status"`) and errors (`role="alert"`), `Skeleton` for loading (with visually hidden "Loading…" text), `Table` in a `Table.ScrollContainer` for version history, and `Pill` for pinned overlay dates. Tests render through `src/test/render.tsx`, which wraps the UI in `MantineProvider`.

## Generated API client

`frontend:generate` writes `src/api/schema.d.ts` from the access OpenAPI document. The file is git-ignored and regenerated by every task that lints, type-checks, tests, builds or runs the app, so the types cannot drift from the contract. `src/api/client.ts` exports the typed `api` client, which calls `VITE_ACCESS_URL`.

## Curve view

The page shows the ECB euro area AAA spot curve (`curve_id` `ecb-aaa-spot`, or its simulated twin, see Curve choice below) after the health check passes. The layout follows the calm editorial pattern: `PageHeader` with title "Yield curve", a one-line subtitle that depends on the curve (real vs simulated), valid date and overlay actions, a row of `StatCard` key figures, a chart card and a values table card.

- **Latest curve:** on open, the view calls `GET /v1/curves/{curve_id}/observations` without `valid_date`; the date input then shows the `valid_date` the API returned.
- **Valid date:** in the page header, with an info tooltip (ECB business day). Picking a date refetches for that date. Clearing the input returns to the latest curve.
- **Key figures:** 10Y yield (`formatYield`, 3 dp), 2Y–10Y spread in basis points (`spread2s10s` and `formatBp`, signed), curve date and knowledge (`Live` or `formatUtc(asOf)`).
- **Gaps:** maturities without a published value (`value: null`) are plotted as gaps, not zeros, and listed in dimmed text under the chart ("No value for: …"). Points keep the API's grid order.
- **Values table:** every grid maturity with yield to three decimals and a subtle "History" row action (`aria-label` "History {maturity}").
- **Errors:** 404 shows "No data known for this date."; 422 and other errors show the problem `detail`; 503 or an unreachable API shows the offline alert.
- **Attribution:** the source is in the footer (see [Layout](#layout)).

### Overlay

"Add to overlay" (header, default button) pins the valid date currently shown, so the chart compares several dates of the same curve.

- **Pinning:** up to 5 dates; the button is disabled at 5, for a date already pinned, and when no curve is shown. Each pinned date appears as a `Pill` in the chart card header (`aria-label` "Overlaid valid dates") with "Remove <date>".
- **Chart:** card title "Spot curve (%)", linear axes with `domain: ['auto','auto']`, legend only when two or more series, tooltips at 3 dp. The shown curve is drawn first, then each pinned date as its own line, named by its valid date in the legend. A pinned date equal to the shown one is not drawn twice.
- **Data:** each pinned date is fetched with the current `as_of` (from `App`), and all are refetched when `as_of` changes. A pinned date with no data at the chosen time is left out of the chart.
- **Scope:** overlays compare valid dates only; countries are not overlaid.

## Time series

The "Time series" view shows one maturity of the same curve (`ecb-aaa-spot`) over a range of valid dates, via `GET /v1/curves/{curve_id}/maturities/{maturity}/observations`. The layout matches the curve view: `PageHeader`, a row of `StatCard` key figures, then one card with a chart or values table.

- **Header:** title "Time series", subtitle "{maturity} yield over valid dates (%)", and actions for maturity and the date range.
- **Maturity:** a select over the 11 grid tenors (3M to 30Y); it defaults to 10Y and refetches on change.
- **Range:** "From" and "To" date inputs default to the last 365 days up to today (UTC). Dates without a value are absent from the series, not zeros.
- **Key figures:** last, min and max yield (`formatYield`, 3 dp) and change over the range in basis points (`seriesStats` and `formatBp`, signed, true minus).
- **Chart or table:** a `SegmentedControl` toggles chart and table in one card titled "{maturity} yield (%)". The chart is a linear Mantine line over valid dates (`curveType` linear, `domain: ['auto','auto']`, dots when ≤ 15 points, brush, tooltips at 3 dp, no animation, colour `CHART_COLORS[0]`, no legend). The table lists valid date and yield (%) with right-aligned 3 dp values.
- **Known as of:** the shared header status and `as_of` URL parameter, so the choice carries across all views.
- **Errors:** as for the curve view; 404 shows "No data known for this maturity."
- **Navigation:** the header tabs "Curve", "Time series", "Changes" and "Quality" switch views from `sm` up; below `sm` the Burger opens the navbar with the same views. The curve view is the default.
- **Attribution:** the source is in the footer (see [Layout](#layout)).

## Charts

Both charts use `@mantine/charts` (a Recharts wrapper) and share the theme and the `@mantine/charts/styles.css` import in `src/main.tsx`. Plotly.js was removed in PR 3 of #153.

- **Colours:** `CHART_COLORS` in `src/theme.ts` (`blue.8`, `orange.8`, `teal.8`, `grape.8`, `pink.8`, `lime.9`) in a fixed order, the same in light and dark. Series are never cycled past six.
- **Curve chart:** one row per maturity in grid order, one line per curve. A maturity without a value is a gap (`connectNulls` off). Legend shows the valid dates. Data is built by `overlayRows` and `overlaySeries` in `src/curve/curveData.ts`.
- **Time series chart:** one line over valid dates in valid-date order, linear axes with `domain: ['auto','auto']`, dots when ≤ 15 points, brush to zoom the range, tooltips at 3 dp, no legend (the card title names the series). A table toggle in the same card lists the same points.
- **Lazy loading:** each chart module imports `@mantine/charts` with `lazy`/`import()` and renders it inside `Suspense` with a 320 px skeleton, so the charting code is a separate chunk (`dist/assets/chunk-*.js`) that loads with the first chart.
- **Bundle budget:** `npm run size` (`size-limit`, `frontend:size`) checks gzipped sizes of the bundle: initial entry (`index-*.js`) at most 170 kB, all JS at most 500 kB, CSS at most 45 kB. The all-JS limit was raised from 320 kB to 330 kB on 2026-10-20 by the user for the design system MRs (#165), and raised to 500 kB on 2026-10-20 by the user. Vite names lazy chunks `chunk-*.js` so the entry is not confused with them. CI runs the check after the build.

## Changes view

The "Changes" tab shows which values differ between two knowledge states, via `GET /v1/curves/{curve_id}/changes`.

- **Header:** title "Changes", subtitle "What changed in the data between two knowledge times".
- **Controls:** a card with "From" and "To" valid-date inputs (default last 365 days to today, UTC) and "Compare from (known as of)" (`datetime-local`, description "Your local time, shown in UTC elsewhere", info tooltip on the earlier knowledge time). Until compare-from is set the view shows an empty state (`role="status"`: "Pick a starting point" / "Choose the earlier knowledge time to compare.") and sends no request.
- **Known as of:** the shared header status and `as_of` URL parameter; Live (the default) compares with the latest knowledge.
- **Table:** in a card, one row per changed value in API order: valid date, maturity, old and new yield (`formatYield`, 3 dp, right-aligned), change in basis points (`formatBp`, signed, true minus, right-aligned), reason badge (sentence case: `correction` orange, `revision` blue, others gray), source and known from (`formatUtc`). Old value and source show "–" when absent; the change shows "–" when the value was not known at the earlier time.
- **No rows:** "No changes between these knowledge times."
- **Errors:** 404 and 422 show the problem `detail`; 503 or an unreachable API shows the offline alert.

## Data quality

The "Quality" tab shows the plausibility and completeness checks per TARGET business day of the curve, via `GET /v1/curves/{curve_id}/quality`. The results are fetched when the tab is first opened, like the other views.

- **Header:** title "Data quality", subtitle "Plausibility and completeness checks per business day, {curve label}", and the From and To valid-date inputs as page actions (as in the time series view).
- **Controls and validation:** the range defaults to the last 30 days up to today (UTC). To must not be before From, and the span may be at most 365 days (366 dates). An invalid range shows the error under "To" ("To must be on or after From." or "Choose a range of at most 366 days.") and sends no request. While the range is invalid the body is empty; the method card below stays.
- **Loading:** four stat-card skeletons (height 104), a table skeleton (height 180) and visually hidden "Loading…".
- **Stat cards:** "Days checked" (checked days, hint "of {n} business days"), "Warnings" (warn findings, hint "on {n} days"), "Info flags" (info findings, hint "on {n} days") and "Last check" (newest `checked_as_of`, `formatUtc`; "–" with the hint "No check results known at this time" when none is known).
- **Table:** a card titled "Checks per day" with one row per valid date, newest first, in a `Table.ScrollContainer` with a minimum width of 720 px. Columns: valid date, status (a `Badge` with icon and word: Passed, Info, Warn or Unchecked, see `qualityBadgeProps`), findings and checked as of (`formatUtc`, "–" when unchecked). Findings list warnings before info (`sortFindings`), each as a flag (Q1 below). A partly checked day adds "Not checked: {rules}" under its findings, for example "Not checked: Jump".
- **Filter:** a `SegmentedControl` labelled "Show days" with All, Warn, Info and Unchecked. A filter with no matching day shows the empty state "No days match this filter" with the action "Show all days".
- **Flags (Q1):** a `Popover` (click or Enter, not hover, so it works from the keyboard) around a `Badge` button labelled "{rule} · {severity}", with the rule's title and the API's explanation and evidence in the dropdown, and the "How we check this" link to the method. The button's accessible name adds the maturity, for example "Jump · warn, 10Y".
- **How we check:** a card at the bottom of every state, with one accordion item per rule (range, jump, missing date, missing maturity) and a link "Read the full method".
- **States:** no business days in the range shows "No business days in this range" with "Show last 30 days" (which also refetches the default range). A 404 shows "No quality results for this curve". A 503 or an unreachable API shows the offline alert "Backend offline" with "Try again". A 422 or other error shows "Could not load quality results" with the problem `detail` and "Try again".

## Version history

Each shown value can be traced to the versions it had, via `GET /v1/curves/{curve_id}/maturities/{maturity}/observations/{valid_date}/versions`.

- **Entry:** the curve values table has a "History" button per maturity with a value (`aria-label` "History {maturity}"). It opens a right-hand `Drawer` titled "History of {maturity} on {valid_date}"; the drawer close control is labelled "Close".
- **Scope:** it shows the maturity, the valid date currently shown and the current "Known as of" time (`as_of`, from `App`). It refetches when `as_of` changes.
- **Table:** one row per version, oldest first as the API returns them, with value (3 dp, right-aligned), "Known from", "Known until" ("current" while the version is still current), reason badge, source, run and delivery. Times use `formatUtc`. Missing source or delivery shows "–".
- **Errors:** as for the curve view; 404 shows "No data known for this value." (or "No data known as of …" with `as_of`); 422 and other errors show the problem `detail`; 503 or an unreachable API shows the offline alert.

## Time travel

The "Known as of" time shows every view as it was known at a chosen time (the API's `as_of`, the transaction-time axis, separate from the valid date). `App` holds the one value and passes it to each view as the `asOf` prop, so a change on one tab applies to all tabs.

- **Status:** a header button, shown once the backend is online, labelled "Live" (default variant) when no time is set, or "As of 19 Oct 2026, 18:49:25 UTC" (yellow.5, filled) for a past time. It sits in a `role="status"` region, so changes are announced.
- **Popover:** the button opens a Popover (focus is trapped inside it, Esc closes it and returns focus to the button; Enter or Space opens it) with the "Known as of" `datetime-local` input (read as local time, sent as UTC ISO; description "Your local time, shown in UTC elsewhere"), a "Now" button that returns to the latest knowledge, and an explanation of the choice.
- **URL:** the choice is kept in the `as_of` query parameter, so a link reproduces the view. A missing or unparseable `as_of` is ignored. Changes use `history.replaceState`, so they add no history entries.
- **No data:** if nothing was known at that time (404), the view shows "No data known as of …"; a 422 shows the problem `detail`.
- **Times:** knowledge times are shown in UTC by `formatUtc` (`src/format.ts`).

## Curve choice

The header offers two curves, both served by the API: "Real" (`ecb-aaa-spot`) and "Simulated" (`ecb-aaa-spot-sim`, scenario data). The choice applies to the curve and time series views.

- **Control:** a segmented control labelled "Curve" in the header from `sm` up, and in the navbar below `sm`. It is shown once the backend is online and defaults to "Real".
- **Simulated:** choosing "Simulated" shows one orange "Simulated" badge in the header and one note above the views ("Simulated scenario data, not an ECB publication.", `role="note"`). The footer then says the data is scenario data, not an ECB source.
- **URL:** the choice is kept in the `curve` query parameter (`?curve=ecb-aaa-spot-sim`), written with `history.replaceState` like `as_of`. A missing or unknown value falls back to the real curve.
- **Views:** switching the curve resets the view state (pinned overlays, open history). The curve view title stays "Yield curve"; its subtitle and the simulated badge and note identify the curve.

## Offline state

On mount the app calls `GET {VITE_ACCESS_URL}/health` (`src/backend.ts`). A `2xx` response shows the views; a non-2xx response or a network error shows a `role="alert"` message ("Backend offline: the YieldLens API is not reachable. Try again later.") with a "Try again" button that repeats the check. While the check runs, the page shows a 320 px skeleton with visually hidden "Loading…". Both states are inside the app shell, so the header and footer stay visible.

## Hosting

The live app is served by GitHub Pages at `https://maxbernstetter.github.io/yield-lens/`. `vite build --mode pages` (task `frontend:build:pages`) sets the base path to `/yield-lens/`; the dev server, `build`, `preview` and the e2e tests keep base `/`. The access API is the VM behind Caddy (see [[09-deployment]]). If the VM is down, the offline state above is shown. The workflow is `.github/workflows/pages.yml`; it is skipped until `VITE_ACCESS_URL` is set on the `github-pages` Environment.

## Layout

The page is a Mantine `AppShell` with a 56 px header, the body and an in-flow footer. The default colour scheme is light; the header's toggle switches to dark and back.

- **Display range:** desktop only, 1280–1920 px wide (decided by the user on 2026-10-20). Phone widths (390 px) are not supported. The Navbar below `sm` is legacy and kept as is.
- **Header:** the Burger (below `sm`), the name "YieldLens", the view tabs (a `nav` labelled "Views", from `sm`) and the curve choice (from `sm`), the Simulated badge when the simulated curve is shown, the "Known as of" status (see Time travel), and the colour-scheme toggle, an `ActionIcon` with `aria-label` "Toggle colour scheme".
- **Navbar (below `sm`):** a `nav` labelled "Views" with one Mantine `NavLink` per view (the active one has `aria-current="page"`) and the curve choice, opened by the Burger and closed after a choice.
- **Body:** `Container` at 1200 px; the page title is its `h1` (`PageHeader`); sections are cards. The background comes from the theme.
- **Footer:** below the body, not fixed. Left: the ECB source and copyright notice (or, for the simulated curve, that the data is scenario data). Right: API docs, Methodology (the plausibility note on GitHub), GitHub and `v{version} · {commit}`.
- **Theme:** all styling lives in `src/theme.ts` (see ADR 0018). No CSS files and no `style` props.
