# Frontend

The user frontend (`src/frontend/`) is a static React single-page app that calls only the public `access` API. It is deployed to GitHub Pages (see [[0005-react-spa-on-github-pages]]).

## Stack

| Part | Choice |
|---|---|
| Build and dev server | Vite 7 |
| UI | React 19, TypeScript, Mantine 9 (`@mantine/core`, `@mantine/hooks`), theme in `src/theme.ts`; see [[0018-mantine-ui-and-charts]] |
| Charts | `@mantine/charts` (Recharts), lazy-loaded; see [Charts](#charts) |
| Unit tests | Vitest 5 with jsdom, Testing Library, jest-dom |
| Lint | ESLint 9 with typescript-eslint and react-hooks rules |
| API client | `openapi-fetch`, types generated by `openapi-typescript` from `src/contracts/openapi/access/v1.json` |

Dependencies are pinned to exact versions in `package.json`; `package-lock.json` is committed and is never edited by hand.

## Views

The views are built from Mantine components: `Title` for headings, `TextInput` and `NativeSelect` for controls (native inputs underneath, so date and time pickers stay browser-native), `Button` for actions, `Alert` for the as-of banner (`role="status"`) and errors (`role="alert"`), `Skeleton` for loading (with visually hidden "Loading…" text), `Table` in a `Table.ScrollContainer` for version history, and `Pill` for pinned overlay dates. Tests render through `src/test/render.tsx`, which wraps the UI in `MantineProvider`.

## Generated API client

`frontend:generate` writes `src/api/schema.d.ts` from the access OpenAPI document. The file is git-ignored and regenerated by every task that lints, type-checks, tests, builds or runs the app, so the types cannot drift from the contract. `src/api/client.ts` exports the typed `api` client, which calls `VITE_ACCESS_URL`.

## Curve view

The page shows the ECB euro area AAA spot curve (`curve_id` `ecb-aaa-spot`) after the health check passes.

- **Latest curve:** on open, the view calls `GET /v1/curves/{curve_id}/observations` without `valid_date`; the date input then shows the `valid_date` the API returned.
- **Valid date:** picking a date refetches for that date. Clearing the input returns to the latest curve.
- **Gaps:** maturities without a published value (`value: null`) are plotted as gaps, not zeros, and listed under the chart ("No value for: …"). Points keep the API's grid order.
- **Errors:** 404 shows "No data known for this date."; 422 and other errors show the problem `detail`; 503 or an unreachable API shows the offline alert.
- **Attribution:** the page credits [ECB statistics](https://data.ecb.europa.eu/) as the source.

### Overlay

"Add to overlay" pins the valid date currently shown, so the chart compares several dates of the same curve.

- **Pinning:** up to 5 dates; the button is disabled at 5, for a date already pinned, and when no curve is shown. Each pinned date is listed with a "Remove <date>" button.
- **Chart:** the shown curve is drawn first, then each pinned date as its own line, named by its valid date in the legend. A pinned date equal to the shown one is not drawn twice.
- **Data:** each pinned date is fetched with the current `as_of`, and all are refetched when `as_of` changes. A pinned date with no data at the chosen time is left out of the chart.
- **Scope:** overlays compare valid dates only; countries are not overlaid.

## Time series

The "Time series" view shows one maturity of the same curve (`ecb-aaa-spot`) over a range of valid dates, via `GET /v1/curves/{curve_id}/maturities/{maturity}/observations`.

- **Maturity:** a select over the 11 grid tenors (3M to 30Y); it defaults to 10Y and refetches on change.
- **Range:** "From" and "To" date inputs default to the last 365 days up to today (UTC). Dates without a value are absent from the series, not zeros.
- **Chart:** a Mantine line over valid dates, in valid-date order, with a brush below to narrow the range.
- **Known as of:** the same control and `as_of` URL parameter as the curve view, so the choice carries across both views.
- **Errors:** as for the curve view; 404 shows "No data known for this maturity."
- **Navigation:** "Curve" and "Time series" buttons switch views; the curve view is the default.
- **Attribution:** the page credits [ECB statistics](https://data.ecb.europa.eu/) as the source.

| `src/series/fetchSeries.ts` | API call and mapping of responses to `SeriesResult` |

## Charts

Both charts use `@mantine/charts` (a Recharts wrapper) and share the theme and the `@mantine/charts/styles.css` import in `src/main.tsx`. Plotly.js was removed in PR 3 of #153.

- **Curve chart:** one row per maturity in grid order, one line per curve (palette `indigo`, `teal`, `orange`, `grape`, `cyan`, `pink`, cycled). A maturity without a value is a gap (`connectNulls` off). Legend shows the valid dates. Data is built by `overlayRows` and `overlaySeries` in `src/curve/curveData.ts`.
- **Time series chart:** one line over valid dates in valid-date order, with a brush to zoom the range; markers off.
- **Lazy loading:** each chart module imports `@mantine/charts` with `lazy`/`import()` and renders it inside `Suspense` with a 320 px skeleton, so the charting code is a separate chunk (`dist/assets/chunk-*.js`) that loads with the first chart.
- **Bundle budget:** `npm run size` (`size-limit`, `frontend:size`) checks gzipped sizes of the bundle: initial entry (`index-*.js`) at most 170 kB, all JS at most 300 kB, CSS at most 45 kB. Vite names lazy chunks `chunk-*.js` so the entry is not confused with them. CI runs the check after the build.

## Version history

Each shown value can be traced to the versions it had, via `GET /v1/curves/{curve_id}/maturities/{maturity}/observations/{valid_date}/versions`.

- **Entry:** the curve view has a "History <maturity>" button for each maturity with a value in the shown curve. The panel opens below the buttons and closes with "Close".
- **Scope:** it shows the maturity, the valid date currently shown and the current "Known as of" time (`as_of`). It refetches when `as_of` changes.
- **Table:** one row per version, oldest first as the API returns them, with value, "Known from", "Known until" ("current" while the version is still current), reason, source, run and delivery. Missing source or delivery shows "–".
- **Errors:** as for the curve view; 404 shows "No data known for this value." (or "No data known as of …" with `as_of`); 422 and other errors show the problem `detail`; 503 or an unreachable API shows the offline alert.

## Time travel

The "Known as of" control shows the curve as it was known at a chosen time (the API's `as_of`, the transaction-time axis, separate from the valid date).

- **Control:** a `datetime-local` input, read as local time and sent as UTC ISO. "Now" clears it and returns to the latest knowledge.
- **URL:** the choice is kept in the `as_of` query parameter, so a link reproduces the view. A missing or unparseable `as_of` is ignored. Changes use `history.replaceState`, so they add no history entries.
- **Banner:** while `as_of` is set the page shows "Showing the curve as known on …" in UTC.
- **No data:** if nothing was known at that time (404), the page shows "No data known as of …"; a 422 shows the problem `detail`.

|---|---|
| `src/asOf.ts` | Read and write `as_of` in the URL; local and UTC conversion |
| `src/curve/AsOfControl.tsx` | "Known as of" input and "Now" button |

## Offline state

On mount the app calls `GET {VITE_ACCESS_URL}/health` (`src/backend.ts`). A `2xx` response shows the curve view; a non-2xx response or a network error shows a `role="alert"` message ("Backend offline: the YieldLens API is not reachable. Try again later."). While the check runs, the page shows "Loading…".

## Tasks

Run from the repository root with `devbox run -- task frontend:<task>` (see [[13-build-and-ci]]):

| Task | Does |
|---|---|
| `frontend:setup` | `npm ci` from the lockfile |
| `frontend:audit` | `npm audit --audit-level=high`; fails on high or critical findings |
| `frontend:generate` | Generate `src/api/schema.d.ts` from the access OpenAPI document |
| `frontend:fmt` | ESLint with `--fix` |
| `frontend:lint` | ESLint |
| `frontend:typecheck` | `tsc -b` (app and Vite config) |
| `frontend:test:unit` | Vitest, single run |
| `frontend:build` | Production bundle in `dist/` |
| `frontend:size` | Bundle budget with `size-limit` on the built `dist/`; depends on `build` |
| `frontend:dev` | Vite dev server on port 5174 (override with `FRONTEND_PORT`; fails if the port is taken) |

CI runs `setup`, `audit`, `lint`, `typecheck`, `test:unit`, `build` and `size` in `.github/workflows/frontend.yml`; each of them generates the API types first, so CI needs no separate step.
